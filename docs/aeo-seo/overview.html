This rubric was assembled by auditing the ReadTomato codebase directly. It is explicit about which parts are established practice and which parts are new — because that distinction changes how much authority each rule carries.

Read this before treating the document as canon

There is no pre-existing formal AEO/SEO framework, rubric or guidelines document anywhere in the repositories reachable from this session. The standard exists as convention encoded in markup — disciplined and consistent, but never written down as a spec. This is the first time it has been. Everything marked new is a proposal, not established doctrine, and should be reviewed before it is adopted.

02 The model

SEO is being retrievable and rankable by a crawler — titles, descriptions, canonicals, headings, internal links, crawl signals. AEO is being quotable by an answer engine. Answer engines lift short, self-contained chunks. They do not lift vibes.

“AI systems pull short chunks that read like clean definitions. Build pages that answer one question at a time. Use clear headers and short paragraphs. When you lead with structure, you increase your odds of being cited.”

“If your advice could apply to any city, AI will not pick you.”

— ReadTomato blog, existing copy

The operating principle that falls out of this: structure is the product. Most AEO work is not new writing. It is cutting existing copy into retrievable units, labelling them honestly, and making the entity behind them unambiguous. That is precisely the work Sitecraft can do without inventing a single fact.

03 The nine-field standard

The one genuinely locked standard we have. It appears verbatim in every blog post, in a comment block that reads: “every blog post must have all 9 fields below. Per-post values; structure is locked.”

  1. SEO title50–60 characters, keyword near the front
  2. Meta description140–155 characters, focus keyword once
  3. Slug / canonicalShort, lowercase, keyword-rich
  4. Focus keyphraseExactly one primary phrase per page
  5. Related keyphrasesSupporting variations and intent terms
  6. Excerpt20–30 words
  7. CategoryOne primary content bucket
  8. Tags5–8 supporting taxonomy terms
  9. Featured image altDescribes naturally, names the topic

Shipping alongside it every time: robots, author, keywords, a full Open Graph block, and a Twitter card.

04 Severity & action class

Every check carries two independent classifications. Severity sets the order work happens in. Action class sets how far Sitecraft may go on its own. Together they are what makes the tool safe to run semi-autonomously.

A

Autonomous

32

Mechanical, reversible, introduces no new claims. Applied without asking — retagging headings, adding a canonical, fixing an @id reference, splitting a long paragraph at an existing sentence boundary.

B

Propose

11

Involves rewording. Sitecraft drafts it, shows a before/after diff citing the check ID, and waits for a human yes. Turning a label H2 into a claim H2 lives here.

C

Flag only

9

Never auto-edited. Reported with the reason it cannot be fixed — anything needing a fact the page does not contain, any rating markup, any author identity, anything in a regulated vertical.

SeverityABCAll
P0 Actively harmful or deceptive. Fix first.2·24
P1 Blocks visibility.10·111
P2 Materially weakens AEO.146525
P3 Polish.65112

Order of work is P0 → P1 → P2 → P3, and within a tier, class A before class B. Note the shape of the matrix: every P0 is either an automatic correction or a hard stop — none of them are left to a judgement call.

The schema graph: Article, Breadcrumb, Organization, Person — and the @id links between them.

JSON-LD parses

Detect
any script[type='application/ld+json'] fails JSON parse
Fix
Repair syntax without altering values.
SCHEMA-02 P1 A · Auto

Primary entity schema present

Detect
no Article, WebPage, Service, Product or LocalBusiness node on a substantive page
Fix
Emit the type matching the page's role, populated strictly from on-page values.
SCHEMA-03 P2 A · Auto

BreadcrumbList present and correct

Detect
BreadcrumbList absent, or positions do not match the site's real nav path
Fix
Derive from the actual nav hierarchy. Final item carries name without item.
SCHEMA-04 P1 A · Auto

@id graph internally consistent

Detect

SCHEMA-05 P2 A · Auto

Dates ISO-8601 with offset, dateModified >= datePublished

Detect
date fields not ISO-8601, missing UTC offset, or dateModified earlier than datePublished
Fix
Normalise format only. Never invent or advance a date.
SCHEMA-06 P3 A · Auto

ImageObject dimensions declared

Detect
ImageObject lacks width/height
Fix
Declare the image's real dimensions. Site convention is 1200x630 for social/article images.
SCHEMA-07 P0 A · Auto

Schema claims match visible content

Detect
headline, description, author or date in schema contradicts the rendered page
Fix
Correct the schema to match the page. Never change the page to match the schema.
SCHEMA-08 P2 B · Propose

FAQPage schema over visible Q&A

Detect
page contains a visible Q&A block with no FAQPage markup
Fix
Mark up the questions and answers exactly as they appear on the page.

SCHEMA-09 P2 A · Auto

Fix

SCHEMA-10 P0 C · Flag

AggregateRating and Review integrity

Detect

06 Execution rules

  1. PARSEExtract metadata, schema graph, heading tree, and a copy inventory of every claim on the page.
  2. AUDITRun all 52 checks. Emit findings carrying check ID and severity.
  3. CLASSIFYAssign each finding its action class.
  4. APPLYExecute class A automatically, P0 through P3 in order.
  5. PROPOSEPresent class B as before/after diffs, with the check ID as the rationale.
  6. FLAGReport class C with the reason it cannot be auto-fixed.
  7. VERIFYRe-parse. Confirm JSON-LD still valid, copy claims unchanged, no regressions, changes idempotent.
  8. REPORTWhat changed, what needs a decision, what is blocked.

Four standing rules govern the whole loop. Copy-bound sourcing: every word Sitecraft emits into user-visible content must be traceable to copy already on the page — when it cannot be, the action drops to class C. Structure before prose: the cheapest AEO win is nearly always a heading fix or a schema addition, not new text. Preserve voice: a rewrite that reads like generic SEO copy is a failure even when it scores well. Never trade honesty for a check: a page scoring 100% while overstating what the business does is a worse outcome than a page scoring 60%.

07 The never list

  • Never invent a fact, number, price, credential, date, or location.
  • Never create or alter AggregateRating, Review, rating values, or review counts.
  • Never add schema describing something not visible on the page.
  • Never change an author's identity, bio, or credentials.
  • Never add noindex, or change a canonical in a way that de-indexes a live page.
  • Never keyword-stuff. One focus keyphrase, used naturally.
  • Never delete existing copy to hit a length target — compress instead.
  • Never let a rubric score justify a claim the business cannot support.
Highest-risk rule in the document

Rating markup must correspond to reviews that genuinely exist and are visible on the page. Fabricated review structured data is a manual-action offence and a legal exposure — not merely a ranking risk. This is the one check where the correct behaviour is always to stop and report.

08 Worked audit

Running this rubric against rt-website-2026 shows why the codified version is needed. The standard is excellent where it is applied, and simply absent everywhere else.

8 / 26Pages carrying canonical, Open Graph and structured data
1 / 26Pages inside both the title and description length bands
0FAQPage schema blocks anywhere on the site
85 / 85Images carrying alt text

All seven blog posts plus the testimonials page are fully instrumented. The other eighteen — every market page, every product page, every partner page, the homepage, contact, and both index pages — carry a bare <title> and <meta name="description"> and nothing else. That includes the commercial pages: products/web-reno.html sells AI visibility to dental practices and has no structured data of its own.

On lengths, only products/web-reno.html sits inside both bands. Blog titles run 64–77 characters against a stated 50–60; descriptions range 113–193 against a stated 140–155. And there is no FAQPage markup anywhere, despite our own doctrine naming deep FAQs as a primary AEO and trust mechanism.

Two content-integrity defects

Hero image and alt text carried over from a different post P1

In blog/ai-search-for-seattle-real-estate-leads.html:563-565, the hero src and alt are both from the trust-in-high-ticket-decisions post. The alt reads “Trust in high-ticket decisions wins the deal” on a page about Seattle AI search — and it contradicts the og:image and Article schema, which both correctly point at RT-BLOG-ai-answers-win-first-click.webp. Caught by TECH-04.

One author bio published under six different bylines P1

The bio beginning “Marshall leads new business development and partnerships…” appears under Jim Cronin, Ashley Alexander, Rob Saxe, Sherry Sanchez, Joshua Marshall and Marshall Gill. Each post carries correct Person schema with a distinct @id, so the structured data and the visible bio actively contradict each other on five of six posts. This is the exact E-E-A-T failure the doctrine warns against — “keep human ownership visible” — and it is machine-readable. Caught by EEAT-02.

What is genuinely strong: alt text coverage is complete, the answer-shaped H2 discipline holds across all seven posts without exception, and the @id graph linking author to organization is correctly formed. Where the standard is applied, it is applied well. The pattern is consistent — the discipline lives in the blog pipeline and stops at its edge. That is the gap Sitecraft exists to close.
